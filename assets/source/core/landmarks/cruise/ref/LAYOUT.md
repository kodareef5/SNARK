# Shared cruise layout contract

`author_layout.py` deterministically writes `content/landmarks/cruise-layout.json` from the geometry, production-room and edge-protection modules. The accepted prototype gate established native capacity; the current source extends that same contract to the complete production reconstruction.

The frame uses metres, waterline Y0, +Y up, +Z bow and +X port. **All source instance yaw values are degrees**. Native conversion happens once in the content adapter. Public measurements are 365 m overall length, 48.5 m waterline beam, 57.8 m deckhouse width and 65.8 m bridge width. Published dimensions and inferred values remain separate. The provisional keel at −9.3 m and highest funnel pipes at 75 m are modeling estimates, not builder specifications. The initial 80 m planning estimate was refined against Corey Seeman's actual 2025 broadside photograph; the forward aerial is lower, at 70.5 m.

Each `prototype` owns a stable namespaced definition/mesh ID, category, palette colour, local collision boxes/convex hulls, complete optional far `look`, local `visualBounds` and original art parameters. Each `instance` owns a stable placement ID, prototype reference, `at`, degree `yaw`, actual deck label, section and `placed` flag. Prototype geometry remains within ±16 m per axis, a conservative 14.5 m horizontal radius, and at most 16 collision parts. This preserves the native route margin after stretch/quantization and the largest creature radius. Optional `look` replaces the native far representation, so it retains essential geometry as well as ornament. Repeated geometry is instanced, not registered under new mesh IDs.

`decks` contain actual string labels (2–12 and 14–20), ordinal index, explicit `floorY`/`ceilingY`, polygon `outlines` and `voids`. Upper levels are partial footprints. Each outline/void polygon is an array of `[x,z]` positions. Floor elevations are inferred from the actual builder photograph and the dated visitor plan: 3.2 m accommodation spacing, taller public levels and a stepped upper stack. This is not authenticated construction CAD.

Vertical floor batches retain every original convex floor fragment, with at most 16 parts inside a 20×20×30 m envelope. A stacked instance's `deck` is its lowest source level; `decks` and `sourceInstances` preserve the complete provenance. Geometry-based support queries remain authoritative. `guardRuns` record original protected endpoints and the placed modules covering each run, so the independent native-frame audit can measure diagonal reuse without assuming ideal rotation.

`graph.nodes` have `{id,at,deck,kind}`. `routes` explicitly join node IDs with ordered ship-local floor anchors and clear width/height. Room bounds, entries and targets are ship-local. Optional room `footprint:{polygons,holes}` describes occupied X/Z plans; absent means the whole rectangular room. It does not make an unsupported region walkable. Portals join graph nodes/room IDs with a ship-local opening centre, normal and clear dimensions. Stairs record source/destination deck labels, placed instance IDs, actual upper floor opening and ordered route. No all-room geometric connector search is required.

Optional cabin doors use reciprocal closed/open **prototypes** and one initially placed closed instance. `doors` identifies the instance, closed/open prototypes, ship-local hinge and clear dimensions; each placement persists independently. Static room structure does not swap with the leaf.

`docking` publishes the authoritative port gangway and terminal anchors. Initial arrival is the deck5 Royal Promenade at Y14; the quay-side landing is `[58,14,-24]`, with a 2.8 m clear gangway. `views` provide reproducible floor positions and targets, labeled `walk` or `spectator`. Pools remain explicitly decorative basins and never register upper-deck map-water columns.
