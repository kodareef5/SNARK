# Reed mat floor material

Completed an original, endless split-reed mat: **2048 × 2048**, **1.5 × 1.5 metres**, **40 strips in each direction**, with a **two-over, two-under twill**. The nominal strip pitch is **37.5 mm** and one pixel represents **0.732421875 mm**. All four maps use the same warped strip coordinates, crossing geometry, and surface details. There are no borders, bindings, holes, or transparent pixels.

The **full encoded height range is 8 mm**: zero means 0 mm and 65535 means 8 mm. The delivered surface occupies approximately **1.304–5.240 mm**, giving about **3.936 mm** of actual relief. Do not stretch that occupied range to eight millimetres when importing it.

The source is original and was generated using the **built-in image generation tool**, from the description alone. No reference pictures were searched for or downloaded, and no existing game material was used or imitated. The supplied repository wood material was viewed as a quality benchmark. Its pixels were not used.

The exact prompt is retained in [generation_prompt.txt](generation_prompt.txt). [source/generated_reed_atlas.png](source/generated_reed_atlas.png) is the unmodified **1254 × 1254** generator output. [source/composed_ribbon_surfaces.png](source/composed_ribbon_surfaces.png) is the computed **2048 × 5120** master containing eighty 2048-pixel-long, 64-pixel-wide ribbon surfaces. Three source patches contribute around each ribbon's length; all sampling, variation, and joins close periodically. The 2048 material is assembled at its final resolution, rather than enlarged from a smaller woven image. Procedural fibres contribute approximately **0.04591 mm RMS** displacement before wear attenuation; the final base's one-pixel high-pass RMS is **3.10872 encoded levels**.

[source/derivation.npz](source/derivation.npz) preserves the full-resolution strip coordinate fields, horizontal/vertical visibility, coverage, wear, and native fibre displacement for inspection. [source/build_metadata.json](source/build_metadata.json) records the seed, scale, source digest, source dimensions, and build duration. These are computed support files and are regenerated by the build.

The first visual pass showed excessive long-strip colour banding. I reduced the per-strip tint differences and introduced more local longitudinal variation, then made a few small edge splits and lifted fibres clearer. In the final 3×3 view I see a continuous, softly irregular weave without a visible tile boundary or a conspicuous stain identifying the repeat. The half-offsets preserve crossings through the middle joins. The normal and height maintain the same outlines and fibre directions; reversing the relighting direction moves edge lighting to the opposite side as expected. The 1:1 views retain small fibres and narrow splits without requiring baked crossing shadows in the base.

All numerical checks are recorded in [checks/metrics.json](checks/metrics.json). Wrap error is the average difference between the last and first samples along an axis. The comparison is the 95th percentile of average differences between neighbouring interior rows or columns. Values below are in 8-bit-equivalent units, including height. Opposite edge pixels represent adjacent samples and do not need to be identical.

Rebuild offline from the frozen source with [build_material.py](build_material.py), then validate and recreate the inspection images with [check_material.py](check_material.py). The dependency versions used are pinned in [requirements.txt](requirements.txt).

```sh
python3 build_material.py
python3 check_material.py
```

A second build of the final script reproduced **every pixel of all four maps exactly**. [checks/rebuild_baseline.json](checks/rebuild_baseline.json) preserves the pre-rebuild pixel hashes; the comparison results and current file hashes are in `checks/metrics.json`. Pixel equality is checked separately from file equality because an ICC profile can contain creation-time metadata. When intentionally changing the material, refresh or remove the baseline before validating the new version.

Enable **sRGB for base only**. Import height, normal and ORM as linear data, use OpenGL normal orientation, and enable repeat addressing on both axes. One UV tile covers 1.5 metres. The normal strength already incorporates that physical scale.

Remaining limitations: this is an authored material, not a measured scan. Fine pigment versus relief separation in the generated source is approximate. Roughness is an artistic estimate; AO is a sampled heightfield approximation and cannot account for hidden undercuts between true three-dimensional ribbons. Frays are deliberately small and represented in colour/height rather than separate geometry. The exact weave and its subtle colour arrangement necessarily recur every 1.5 metres; sustained inspection can still find repeats. I have not evaluated engine-specific texture compression, mip filtering, or parallax/displacement settings.
